# Protocol Buffers (ProtoBuf)
Protocol Buffers is a method to efficiently serialize structured data developed by Google. They are language neutral, platform neutral, and extensible. It is like JSON but smaller and faster, and it generates native language bindings.

Protocol Buffers can be up to a few megabytes in size, and can be used for ephemeral network traffic and and long term data storage. 

**pros:**
- compact data storage
- fast parsing
- compatible across many languages
- functionality is compiler optimized per class

**cons:**
- it is assumed the whole message can be loaded into memory, for data greater than a few megabytes use something else
- you cannot compare two messages without fully serializing them
- messages are not compressed, and special purpose algorithms like PNG can be more efficient
- you cannot fully interpret a message without its `.proto` file
- there are gains to be had for use cases involving large, multidimensional arrays and floating point numbers. `FITS` can be better for reducing overhead.
## Practical
Messages and services are the described in `.proto` files generated by engineers and the proto compiler is invoked at build time to generate a language to generate code in different programming languages. Each class contains simple accessors for each field and methods for serializing/parsing the whole structure.

Example proto message
```js 
edition = "2023";

message Person {
  string name = 1;
  int32 id = 2;
  string email = 3;
}
```

Example using that generated message
```js
Person john = Person.newBuilder()
    .setId(1234)
    .setName("John Doe")
    .setEmail("jdoe@example.com")
    .build();
output = new FileOutputStream(args[0]);
john.writeTo(output);
```
